# stock2 初始策略与增强策略对比方案

## 目标

在保留 stock2 原始迁移策略作为基线的前提下，复制出两条增强策略，用于对比增强过滤对命中质量、回撤和行业聚集效果的影响。

## 策略分组

| 类型 | 策略名 | 说明 |
| --- | --- | --- |
| 基线 | stock2底部共振初始策略 | 保留原始迁移逻辑，不启用增强过滤 |
| 基线 | stock2放量KDJ突破初始策略 | 保留原始迁移逻辑，不启用增强过滤 |
| 增强 | stock2底部共振增强策略 | 在底部修复信号上叠加市场环境、行业广度和风险过滤 |
| 增强 | stock2放量KDJ突破增强策略 | 在放量 KDJ 突破信号上叠加强势趋势、健康放量和风险过滤 |

## 增强模式设计

增强策略通过 `strategy_group.aggregation.filters` 启用，不改变 `strategy_group` 表结构，也不影响未配置 filters 的基线策略。

### market_regime

用全市场最新指标近似判断市场环境。当前实现以 `ma5 >= ma20` 为主要趋势修复条件；若均线不可用，则降级使用 `ma5_delta > 0` 或 `change_pct > 0`。增强策略要求全市场趋势修复比例达到阈值：

- 底部增强：`market_breadth >= 0.20`
- 放量突破增强：`market_breadth >= 0.20`

### sector_breadth

按 `stock_basic.industry` 计算行业内趋势修复比例，要求信号个股所在行业不是孤立修复：

- 底部增强：行业样本数 `>= 5` 且 `sector_breadth >= 0.30`
- 放量突破增强：行业样本数 `>= 5` 且 `sector_breadth >= 0.35`

当前阈值按 2026-05-29 弱市环境校准：当日全市场趋势修复广度约 24%，若直接使用 35%-40% 的强市门槛会导致增强策略无信号，不利于与基线策略做横向对比。

### risk_filter

过滤 ST/退市风险、低换手、极端涨跌幅和过大振幅，降低不可交易或诱多/下跌中继信号：

- 底部增强：`turnover_rate >= 0.3`，`-8 <= change_pct <= 8.8`，`amplitude <= 12`
- 放量突破增强：`turnover_rate >= 0.5`，`-3 <= change_pct <= 9.3`，`amplitude <= 15`

## 对比指标

后续回测应按 `strategy_group_id` 横向比较：

- 当日命中数、行业/概念聚集度
- 原始买入编码 `buy_star` 与新增归一化买入评分的分布
- 信号后 1/3/5/10 日收益
- 最大回撤和止损触发比例
- 命中后 3 日失效率
- 不同市场环境下的收益分布

## 买入评分展示设计

当前事件中的 `buy_star` 来自 `stock_analysis.buy`，是 stock2 老逻辑 `buy_advice_v2()` 产出的原始买入编码，不是 0-5 星级评分。该字段包含大额位编码和风险否决值，例如 MA 支撑、KDJ 底部、底部金叉、BOLL 站上中轨会累加不同位数，出现 BOLL 上轨卖出、成交量卖出、新高背离等风险时可能被置为 `-1`。

为避免影响基线策略和历史事件展示，后续改造必须保留 `buy_star` 的原始含义，不覆盖、不重算为新评分。新增评分应作为独立字段进入信号快照和页面展示：

| 字段 | 含义 | 兼容性要求 |
| --- | --- | --- |
| `buy_star` | stock2 原始 `stock_analysis.buy` 编码 | 保留现状，历史和新老策略都继续展示 |
| `buy_score` | 新增归一化买入评分，建议 0-100 或 0-5 | 新字段，不影响既有策略匹配和历史事件 |
| `buy_signal_code` | 可选，显式保存原始 `stock_analysis.buy` | 若未来要重命名展示，可与 `buy_star` 同值 |
| `buy_signal_reason` | 可选，保存评分解释和加减分原因 | 用于页面解释“为什么是这个评分” |

推荐实施顺序：

1. 在扫描写入 `signal_snapshot.indicator_snapshot` 时附加 `buy_score`、`buy_signal_code`、`buy_signal_reason`，不改变 `signal_snapshot.buy_star`。
2. 页面中保留原 `buy_star` 展示，同时新增“买入评分/评分解释”区域。
3. 新产生的事件使用新评分；历史事件不强制回填。若后续需要历史对比，再单独做离线回填脚本。
4. 若修正 `buy_star` 的日期对齐问题，应只影响新事件，且在文档和提交说明中明确“不回写历史快照”。

## 后续迭代

增强策略当前只做前置过滤和更严格条件，不改变信号生命周期。下一步应补充信号失效、止损、止盈规则，以及上述独立买入评分，用于从“发现信号”升级为“跟踪信号质量”。
